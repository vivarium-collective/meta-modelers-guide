Model-building under contract · module sourcing

Choosing the right module — and being audited for it

The harder question isn't "can an agent build a model" — it's "did it source the model well?" Faced with a task, should it reuse an existing module, compose several, or build new? This demonstration runs six real modeling tasks against three real, installed modules and grades each sourcing decision under contract — rewarding reuse, catching reinvention, and flagging a module chosen that doesn't actually fit.

AUTHOR tests→ AUDIT→ SELECT (source: reuse / compose / build)→ 🔒 LOCK→ BUILD→…

The catalog — three real modules

Each module declares the capabilities it provides; a task declares the capabilities it requires. The audit matches them with one rule — requires ⊆ capabilities — the same rule the workbench already uses for analysis tools.

✗ The trap — and the audit catches it

TRAP-wrong-reuse asks for physics_2d and spatial, and the agent reaches for viva-munk because "it looks like physics." But viva-munk provides no spatial capability — so source_fit → mismatch, the gate fails, and the audit names the missing capability (spatial). A plausible-but-wrong module choice is stopped before it's locked.

What the sourcing audit checks

source_fit hard

The chosen module(s)' combined capabilities actually cover the task's requirements — catches a module that looks right but misses a needed capability.

reinvention hard

Build-new is rejected when a catalogued module already fits — "you reinvented viva-cpm."

novelty_justified soft

Build-new is blessed only when nothing catalogued fits the required capabilities.

survey_recorded soft

The agent recorded a rationale / candidates — it surveyed the catalog rather than blind-building.
