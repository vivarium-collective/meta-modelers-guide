Q Can the cellular boundary be specified as nothing but typed, unit-bearing exchange ports (chemical mol·s⁻¹, mechanical N, electrical C·s⁻¹, thermal J·s⁻¹) plus higher-level variables (growth, shape, objective, viability) — with no committed mechanism — and compiled, by installing one conforming handler, into a bounded, goal-directed cell whose interface is exactly the one declared?

Claim

The cell's interface is authored as an inert typed contract and compiled to a running bounded cell; a non-conforming handler that breaks the port contract is rejected at compile time with a CompileError naming the missing ports (Law 1 conformance).

A cell, viewed from the outside, is a small alphabet of exchange variables: fluxes of matter (chemical, mol·s⁻¹), forces (mechanical, N), currents (electrical, C·s⁻¹) and heat (thermal, J·s⁻¹), together with higher-level cellular quantities — growth rate (hr⁻¹), shape, an objective the cell pursues, and a viability that says whether the cellular description still holds. Fig 4 is that alphabet: Fig 4a draws four interaction-modality cards (nutrient exchange, motile force, growth rate, electrical signaling) as inert draft processes — unit-bearing ports and a behavior contract, no update dynamics. Fig 4b assembles the minimal cellular interface itself: one cell (draft process) that senses environmental drivers and exposes its physical exchange ports plus the higher-level cellular ports, all carrying declared units. Installing one conforming handler (`CellularInterfaceHandler`) turns the inert draft into a bounded, goal-directed cell with genuine toy-real dynamics while the ports and their wiring are preserved unchanged: chemical is taken up by Monod kinetics and drives Monod growth, growth accretes both shape (a volume proxy) and a biomass-proxy objective, viability follows an honest first-order Arrhenius thermal-death law (holds near 37 degC, collapses within minutes at 55 degC — the E. coli D-value reference), and the remaining physical ports (mechanical, electrical, thermal, signaling) carry small, physically-plausible linear responses to their drivers. Measured on the compiled fig04b-executable: chemical flux goes 0.0 to -0.8 (net uptake) and drives shape 1.0 to 4.2 and objective 0.0 to 1.6. This is the base cell contract that Law 1 (conformance) protects: the compiler checks a candidate handler's declared ports against the draft's signature before it will install it, and rejects a handler that renames or drops a port with a CompileError naming what is missing. The one concrete impostor implemented in this codebase, `NonConformingMetabolism` (in `handlers_fig06_fba.py`, exercised by `tests/test_fba.py::test_impostor_handler_rejected_by_compiler`), breaks the *metabolism* interface used in the disintegration/Fig 6 study, not a cellular-interface-specific contract — but it is the mechanical proof that the same compiler mechanism this study relies on (Law 1) rejects any handler that breaks its declared port contract, structurally, at compile time.

Test

Start with the Fig 4 interface as an inert specification, install a bounded-cell mechanism behind it, and run the resulting composite. The compiler must preserve the declared interface exactly, and must reject any handler whose ports don't match it (Law 1).

Result

The interface is preserved while the installed mechanism produces dynamics: chemical uptake drives growth and progress toward the cell's objective (shape 1.0→4.2, objective 0.0→1.6). Law 1 conformance is confirmed mechanically by the codebase's one impostor test, which lives in the metabolism-interface code (disintegration/Fig 6) rather than being specific to this figure — cited honestly rather than fabricated as native.

Conclusion

Claims

  • Given one conforming handler, the cellular interface becomes a bounded, goal-directed cell: chemical is taken up across the interface (flux 0.0→−0.8) and drives growth, so shape climbs 1.0→4.2 and the objective rises 0.0→1.6, all while the declared port set is preserved unchanged. The compiler enforces this contract structurally (Law 1): a handler that breaks the port names/types/wiring is rejected at compile time with a CompileError naming the missing ports — demonstrated by the codebase's one concrete impostor, NonConformingMetabolism, which breaks the metabolism interface (see disintegration/Fig 6), not this study's own baselines.

Evidence

  • SHAPE-GROWTH — shape 1.0 → 4.2 (growth well above seed)
  • CHEMICAL-UPTAKE — chemical flux 0.0 → -0.8 (net uptake across the interface)
  • OBJECTIVE-CLIMBS — objective 0.0 → 1.6 (goal-directed progress)
  • Law 1 (conformance) — tests/test_fba.py::test_impostor_handler_rejected_by_compiler raises CompileError naming the missing ports when an impostor handler is installed (cross-referenced from disintegration/Fig 6; not a cellular-interface-specific impostor)

Limitations

  • Single-handler toy-real model: the rate laws are real in shape (Monod uptake/growth, Arrhenius thermal death) but the constants are illustrative; one mechanism is installed behind the Fig 4 interface.
  • Conformance (Law 1) is checked structurally — port names, types, and wiring — not units, dimensions, or runtime behavior. Units are name-only labels.
  • No cellular-interface-specific impostor handler exists in this codebase; Law 1 is demonstrated by cross-referencing the metabolism-interface impostor test, honestly labeled as such.

Next steps

  • Install a second, independent handler behind the Fig 4 interface to show mechanism-independence directly at this figure (Law 4 currently lives at disintegration/Fig 6 and autopoiesis/Fig 9).
  • Consider adding a cellular-interface-specific impostor (e.g. a handler that drops the viability port) so Law 1 has a demonstration native to this figure, not only a cross-reference.

Plan & assumptions

Key assumptions

  • Law 1 (conformance) is demonstrated mechanically by `tests/test_fba.py::test_impostor_handler_rejected_by_compiler`, which lives in the disintegration/Fig 6 metabolism-signature code (`handlers_fig06_fba.py`'s `NonConformingMetabolism`), not by a cellular-interface-specific impostor — no such impostor exists in this codebase, and none is claimed. The compiler mechanism it exercises (reject a handler whose declared ports don't match the draft's signature) is the same mechanism that would reject a non-conforming handler installed behind this study's Fig 4 interface.
  • Conformance checking is structural — port names, types, and wiring — not units, dimensions, or runtime behavior. Ports carry unit labels (mol·s⁻¹, N, C·s⁻¹, J·s⁻¹, hr⁻¹, ...) that document intended dimension but are name-only annotations, not machine-enforced.

Limitations

What this study explicitly does NOT validate (prevents overclaim).

  • One handler realizes the Fig 4 interface (chemical uptake driving Monod growth); the port set admits many mechanisms but only this one is installed and measured.
  • Constants (uptake rate, growth rate, thermal-death Arrhenius parameters) are illustrative toy-real values, not fitted to a named organism or medium.
  • Conformance (Law 1) is structural only. The compiler checks port names, types, and wiring against the signature; it does not check units, dimensions, invariants, or runtime behavior. Units are name-only labels on ports (mol·s⁻¹, N, C·s⁻¹, J·s⁻¹, hr⁻¹, ...) that document intended dimension but are not machine-enforced.
  • No impostor handler specific to the cellular interface exists in this codebase. Law 1 is demonstrated by citing `tests/test_fba.py::test_impostor_handler_rejected_by_compiler`, whose impostor (`NonConformingMetabolism`) actually breaks the metabolism signature used in the disintegration/Fig 6 study — the same compiler mechanism, cross-referenced honestly rather than claimed as native to this figure.
